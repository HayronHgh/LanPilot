# LanPilot 發布就緒報告

更新：2026-09-19。狀態：可供兩台既有實機測試的開發版，尚非正式 Release。

## 三條版本線

| 版本 | 表示方式 | 傳輸 | 狀態 |
| --- | --- | --- | --- |
| v0.1 | H.264 | SSH | 保留原有能力；獨立來源／產物仍需驗證後標記 |
| v0.2 | 自研 snapshot／RECT | SSH | 第二條版本線；不是每個研究快照都發布 |
| v0.3 | 自研 snapshot／RECT | visual TLS + control TLS + Agent SSH | 最新開發主線 |

三個邏輯通道不表示三個自訂 TCP port：畫面與控制使用獨立 socket，
目前共用一個 TLS listener port；Agent 使用原有 SSH 服務。
獨立 socket 降低應用層互相阻塞，但共享網路資源，也不保證消除所有延遲。

## 已有證據

- Windows 編譯及 workflow-unit/security CTest 2/2 通過。
- 既有 Mac build／CTest 與正式身份 TLS 連線曾通過；每次發布仍須驗證
  對應的公開 commit，不能沿用不同來源的舊成功紀錄。
- TLS 視訊／控制 admission、完整快照、commit ACK 與重連已有無輸入實機 probe。
- 最新 Exact-only 指標座標問題已修正：snapshot commit 攜帶已驗證尺寸，
  不再因缺少 H.264 frame 而失去滑鼠映射。五組 receiver probe 通過，
  包含中斷、逾時與錯誤 framing；測試不注入鍵鼠。
- 使用者確認最新滑鼠修補可用；不等於所有乾淨環境與長測通過。
- 公開倉庫保留乾淨 commit 歷史；私人設定、身份資料、研究歷史不發布。

## 正式發布 blockers

| 優先 | 缺口 | 完成定義 |
| --- | --- | --- |
| P0 | 首次配對仍需工程操作 | 兩端自行產生本機私鑰、明確核對配對身份、可拒絕／解除配對；不用貼 keychain 指令 |
| P0 | 撤銷資料／憑證更新未自動化 | 到期前更新、驗簽後原子替換、失敗重試與提示；過期仍 fail closed，不取消驗證 |
| P0 | 安裝與 OS 權限引導 | 穩定安裝路徑，明確區分螢幕錄製與控制權限；可重試，不重建身份 |
| P0 | 發布來源與雙端產物一致性 | 同一公開 commit 的 Windows/Mac build/CTest、SHA-256、版本清單與依賴授權 |
| P1 | 更新／移除／登入啟動 | 新使用者與乾淨環境驗收；保留設定，失敗可回復；解除配對與移除身份要明確選擇 |
| P1 | 簽章與 macOS 公證 | 有效簽章、公證與 Gatekeeper/SmartScreen 體驗驗證；不要求全域關閉保護 |
| P1 | 最終人工驗收與長測 | 點擊／拖曳／IME／失焦放鍵／斷線／重連／長時間 idle-motion，逐項記錄版本與結果 |

目前本機信任 bundle 壽命有限，不能當成永久可用的部署。
沒有高速攝影及同條件足夠样本，不宣稱 AnyDesk 級 input-to-photon。

## 最短收斂順序

1. 固定 v0.3 主線與公開 CI，保留 v0.1/v0.2 的已驗證來源，不替未驗證版本打標籤。
2. 先補信任資料更新與失敗提示，避免已安裝版本過期失聯。
3. 做首次配對／權限精靈，整合現有身份與使用者服務工具，不再建立平行身份。
4. 同一 commit 產出雙平台套件；乾淨安裝、升級、回復、移除驗收。
5. 使用者完成人工體感驗收，補長測與簽章／公證，通過後才發布正式資產。

工程提交照功能單位保留；只有三條產品版本線，不需每個 commit 都建立 Release。
